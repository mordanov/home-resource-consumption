## Summary

Build a self-hosted, single-user web application that ingests utility bills (electricity, gas, water) via PDF/image upload, extracts structured consumption and cost data using an LLM (OpenAI), persists data in PostgreSQL, generates ML-driven 1–3 month consumption forecasts (scikit-learn), and provides rich analytics charts and a PDF export. The stack is FastAPI (Python 3.12) + React 18 + PostgreSQL 16, containerised with Docker Compose and proxied via Nginx.

## Key Design Decisions

### 1. Bill parsing flow — two-step (upload → confirm)

The upload endpoint returns a preview; the user must explicitly call `/bills/confirm` to persist. This satisfies FR-010 (user review before save) and separates the expensive LLM call from the write operation. The preview is stateless — no temporary DB storage needed; the preview data is held client-side until confirm.

### 2. Prediction model — on-the-fly training

Training happens at request time (`GET /predictions/{resource_type}`). At ≤ 24 data points per resource type, training + inference takes < 200ms. This avoids a separate model serialisation/deserialisation cycle and model-versioning complexity. Model version is encoded in the `model_version` field of `Prediction` for audit.

### 3. Analytics — single summary endpoint

All six chart datasets are returned in one `GET /analytics/summary` response. This reduces round-trips from 6 to 1 and simplifies React Query cache management. The backend performs all aggregations in SQL, returning only pre-computed numbers to the frontend (FR-021 / constitution §3.1 SRP).

### 4. PDF charts — inline SVG from Matplotlib

Matplotlib with the `Agg` backend generates chart data as SVG strings, which are embedded directly into the Jinja2 HTML template. WeasyPrint renders the HTML to PDF inline — no temporary files, no external chart rendering service.

### 5. Soft-delete — query filter convention

Every `BillRepository` method that returns bills applies `WHERE deleted_at IS NULL` unless the method is explicitly named `get_including_deleted`. This is enforced by code review and a repository unit test that seeds a deleted bill and asserts it never appears in standard query results.

### 6. Token refresh — single interceptor, no duplication

The Axios response interceptor in `src/lib/axios.ts` is the only place that handles 401 → refresh → retry. No page-level code or React Query hook reimplements this. The interceptor stores a single in-flight refresh promise to prevent concurrent refresh storms.
